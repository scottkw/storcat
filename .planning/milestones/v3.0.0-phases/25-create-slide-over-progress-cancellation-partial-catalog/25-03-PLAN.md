<objective>
Give the running scan a real off switch and a real salvage path: a second bound call that cancels the in-flight walk, a retained partial tree the user can choose to write, and a window-close path that cancels before the process exits.

Purpose: a Wails-bound method cannot take a context from JavaScript, so cancellation must be a separate call that reaches a handle the first call stored. And the bound method that produced the partial tree has already returned by the time the user decides to save it, so the tree has to be retained somewhere — on the App, never inside the catalog package, which must stay stateless and CLI-safe.

Output: the `CancelScan` and `WritePartialCatalog` bindings, the before-close cancellation branch, and the frontend bridge entries for both.
</objective>

When the service returns, inspect the error: an errors-as match on the source-loss type retains its carried partial scan together with the request parameters and returns the error to the frontend; a cancellation returns without retaining anything; success returns the result.

Add the bound method `CancelScan()` taking the mutex, calling the stored cancel function when it is non-nil, and returning nothing — a cancel with no scan running is a no-op, not an error. Document that the handle is a single field rather than a map keyed by scan id because the product is one-scan-at-a-time by explicit requirement, and that a map would be over-built for it.

Add the bound method `WritePartialCatalog() (*models.CreateCatalogResult, error)`. Under the mutex: when a previously-written result is already cached, return it immediately without touching the filesystem — this is what makes a second click a true no-op rather than a duplicate write or a second rename. Otherwise, when nothing is retained, return an error. Otherwise take the retained tree and request parameters, release the mutex, call the catalog package's shared write path with them, and on success cache the result and clear the retained tree under the mutex again. Never re-walk anything — the tree is what the interrupted scan already produced.

Add a comment on the cancel path recording the accepted limitation that the standard library gives the directory-read and stat calls no cancellation awareness, so a syscall already blocked inside the operating system — the common case for a device that is disconnecting rather than already gone — cannot be interrupted; cancellation is prompt for every syscall that has not yet started, and wrapping each syscall in a goroutine-plus-timeout would add real complexity for a rare, cosmetic worst case.

Extend `app_test.go` with the seven tests named in the behavior block.
