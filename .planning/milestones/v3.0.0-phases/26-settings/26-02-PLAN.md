## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-06 | Tampering | `App.SetTheme` / `App.SetRailSide` — arbitrary strings persisted into `config.json` | low | mitigate | Both values are consumed only through existing allowlists: `getThemeById(id) ?? getDefaultTheme()` for the theme, and `readPersistedPrefs()`'s exact-string `'Left'`/`'Right'` check for the rail side. An injected value can never reach `applyTokens()` or the `data-rail-side` attribute |
| T-26-07 | Tampering | `ThemeGrid` swatch backgrounds written as inline `style.background` values | low | mitigate | Swatch colors come exclusively from the compile-time `themes` array in `frontend/src/themes.ts`, never from config, localStorage, or any binding return value — there is no path for a runtime-supplied string to reach a style property here. The four swatches are `aria-hidden` decoration |
| T-26-08 | Spoofing | A second theme-apply path diverging from `App.tsx`'s listener, leaving the visible theme and the persisted theme disagreeing | medium | mitigate | `setThemeSetting` dispatches the one existing `themeChange` CustomEvent rather than calling `applyTokens` directly; the acceptance criteria pin that no fourth apply path exists |
| T-26-SC | Tampering | npm / Go module installs | high | accept | No package is installed by this plan — 26-RESEARCH.md's Package Legitimacy Audit records "Not applicable" for the whole phase, verified against `frontend/package.json` and `go.mod` |
