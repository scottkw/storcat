Container: a plain `<div>` with `max-height: 200px; overflow-y: auto`. Native scroll, no virtualizer.
This is a deliberate, reasoned choice — a diff has no hierarchy (every `Name` is already a full relative
path, no expand/collapse), and its scale is bounded by what differs rather than by catalog size. Do not
reach for `useVisibleRows`; do not add a virtualization dependency.

Grouping: exactly four groups in the fixed order Added, Removed, Changed, Unreadable. Unchanged entries
are never rendered as rows — they exist only as a tile count. Within each group sort rows alphabetically
by path. A group with zero entries renders nothing at all — no header, no placeholder, no reserved slot.

Group header row: 24px tall, 11px/600 uppercase with 0.05em letter-spacing in `--dm`, no background,
text `"{STATE} · {n}"` (for example `REMOVED · 18`).

Entry row: `padding: 7px 0`, `border-bottom: 1px solid var(--l2)`, `gap: 10px`, three columns —
  1. Mark column, `width: 10px; flex: none`, 12px mono. The glyphs are `+` for added in `--ac`, the
     minus sign `−` (U+2212, matching the handoff) for removed in `--danger`, `~` for changed in
     `#f0b429`, and `!` for unreadable in `--danger`. These are literal text characters in styled spans;
     no SVG, no icon dependency.
  2. Path, 11.5px mono, `flex: 1; overflow: hidden; text-overflow: ellipsis; white-space: nowrap`.
     Single-line ellipsis — deliberately NOT the delete dialog's `word-break: break-all` never-truncate
     treatment, because this is a list of potentially hundreds of rows rather than one path the user must
     verify character by character before an irreversible action.
  3. Right column, `margin-left: auto; flex: none; white-space: nowrap`, 11px mono `--dm`. Added and
     removed rows show the entry's size via the existing `formatBytes` helper. Changed rows show
     `"{oldSize} → {newSize}"`. Unreadable rows show the entry's short read-error reason instead of a
     size — no size is knowable for an entry that failed to read.

Add the matching `.ws-rescan-difflist*` / `.ws-rescan-diffgroup*` / `.ws-rescan-diffrow*` classes to
`workspace.css`. No new CSS custom properties; consume the already-declared tokens only.

Note the explicit scale backstop from the UI-SPEC: native-scroll performance is NOT verified against tens
of thousands of differing rows. Record it in the summary as a known boundary rather than silently
assuming it holds.
