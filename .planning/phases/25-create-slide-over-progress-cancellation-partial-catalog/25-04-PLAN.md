<objective>
Give the create flow a real list of things to catalog, and give the progress bar a real denominator.

Purpose: CRT-02's volume cards need a name, a mount path, a size, and a readable/unreadable status per volume, and none of that exists yet. The same size figure is what makes CRT-07's percentage a real number rather than a spinner in numeric clothing — which is why the phase also needs the count-only pre-pass for the plain-folder case, where no volume total exists.

Output: a new stdlib-only `internal/volumes` package with per-operating-system files, the `ListVolumes` binding, a reusable tree-measurement helper, and two honest platform-gap ledger entries.
</objective>

## Threat model

### Trust boundaries

| Boundary | Description |
|----------|-------------|
| operating-system mount namespace → volume list | The contents of the mount namespace are outside the app's control and include entries that are not user volumes at all |
| renderer JS → `ListVolumes` | Any script in the webview can enumerate the machine's mounted volumes |

### STRIDE threat register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-16 | Information Disclosure | `App.ListVolumes` — mount-point metadata exposed to any renderer script | low | accept | Single-user local desktop application; the webview runs only this app's own bundled assets, and the data is read-only metadata the user can see in any file manager. ASVS level 1 does not require a control here |
| T-25-17 | Denial of Service | `List()` — a hung or failing mount stalling enumeration | medium | mitigate | Readability is probed by opening the mount point and reading a single entry, never by walking it; a candidate whose stat or probe fails contributes a not-readable card instead of failing the whole enumeration |
| T-25-18 | Tampering | Boot volume or vendor-internal mount offered as a catalog target | medium | mitigate | Entries resolving to the filesystem root are excluded, and hidden and vendor-reserved names are filtered by the shared predicate, which is unit-tested on every platform |
| T-25-19 | Denial of Service | `MeasureTree` — an unbounded pre-pass over a very large folder | low | accept | The pre-pass is context-cancellable at every directory boundary and runs only when no volume total is available; the user can cancel from the interface, which cancels the same context |
| T-25-SC | Tampering | Dependency supply chain | high | mitigate | No new package is installed. The only module-graph change is promoting an already-resolved, already-checksummed first-party Go team module from indirect to direct; `25-RESEARCH.md`'s Package Legitimacy Audit records it with an OK verdict and zero `[ASSUMED]`, `[SUS]` or `[SLOP]` rows, so no blocking legitimacy checkpoint is required |
