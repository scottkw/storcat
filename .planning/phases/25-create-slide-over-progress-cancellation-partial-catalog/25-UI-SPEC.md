## Slide-over Shell & Animation Contract (CRT-01)

**Mount pattern:** `WorkspaceShell` always mounts a single `CreateSlideOver` instance (same pattern as `CommandPalette`), receiving the parent-owned `isOpen` boolean. Unlike the palette, this component **must not** unmount the instant `isOpen` goes false — it owns a local `closing` flag so the exit animation is visible:

```
isOpen: false → true   : render immediately, no animation-in delay
isOpen: true  → false  : set closing = true; keep rendering; after 260ms, closing = false
render condition        : isOpen || closing
reopen while closing    : clear the pending 260ms timer, closing = false, render as open immediately
                           (mirrors the handoff's own `clearTimeout(this.closeTimer)` in `openCreate`)
```

**`useModalBehavior({ isOpen, onClose })` is called with the real `isOpen` (not `isOpen || closing`).** This is deliberate and load-bearing, per `24-UI-SPEC.md`'s E6 note written specifically for this consumer: the hook's scroll-unlock and focus-restore fire on the `true → false` transition, i.e. the instant a close is requested — not 260ms later at unmount. The background becomes scrollable and focus returns to the trigger element immediately, while the panel itself keeps visually sliding out for 260ms. Do not gate the hook call on `closing` — that would leave the page scroll-locked for the whole exit animation, the exact bug the hook's design note warns against.

**All five close paths call the same `onClose` prop** (never a bespoke handler per trigger): Escape (handled inside `useModalBehavior`, fires regardless of internal focus), the header `×`, the form-step "Cancel" button, a scrim click (the panel itself stops click propagation, matching the palette's `onClick={{stop}}` convention), and the done-state "Open in workspace" button. **During the `scanning` state there is no separate "Cancel" button** — Escape / `×` / scrim click are the only three applicable paths, and per the Cancellation Contract below they cancel the running scan, not just close a form.

**Animation values (exact, from `README.md`'s Transitions section and the demo's `scslide`/`scslideout`/`scfade`/`scfadeout` keyframes):**

| Element | In | Out |
|---|---|---|
| Panel | `translateX(100%) → 0`, 340ms, `cubic-bezier(.16,.84,.24,1)` | `translateX(0) → 100%`, 260ms, `cubic-bezier(.4,0,.7,.2)` |
| Scrim | opacity 0→1, 200ms, ease-out | opacity 1→0, 260ms, ease-in |

Two **new** keyframe pairs in `workspace.css` (distinct from the palette's existing 100ms `ws-palette-scrim-in` — do not reuse it, the timings differ): `ws-create-scrim-in` / `ws-create-scrim-out` and `ws-create-slide-in` / `ws-create-slide-out`. `will-change: transform` on the panel only. `@media (prefers-reduced-motion: reduce)`: both animations disabled (instant show/hide), same accessibility precedent the palette already set.

Header (52px, flex none, 1px bottom border `--l`): title (15px/600) + step label (11px mono `--fn`) + `×` (16px `--dm`), per this table:

| Step | Title | Step label |
|---|---|---|
| `form` | "New catalog" | "step 1 of 2" |
| `scanning` (incl. the counting sub-state) | "Cataloguing volume" | "step 2 of 2" |
| `error` | "Scan interrupted" | "failed" |
| `done` | "Catalog written" | "done" |

Scrollable body: `flex:1; overflow-y:auto; padding:18px; display:flex; flex-direction:column; gap:20px`.

### Source volume (CRT-02, CRT-03)

Section label "Source volume" (11px/600 uppercase, `0.05em`, `--dm`). One card per detected volume (`padding:10px 12px; border-radius:9px; gap:12px; cursor:pointer`):
- 30×20px chip (`border-radius:3px`) — `--ac` fill when this card is selected, `--fn` otherwise.
- Name (13px/500) + mount path (11px mono `--dm`) — both **single-line, ellipsized** (`overflow:hidden; text-overflow:ellipsis; white-space:nowrap`; unlike the WILL WRITE box, cards keep a fixed compact height and do not wrap).
- Size, right-aligned (11.5px mono `--dm`, `flex:none`).
- Status tag, `flex:none`: `mounted` (11px, `--dm` text on `--ch` fill) or `read errors` (11px, `#f0b429` text on `rgba(240,180,41,.14)` fill), `border-radius:5px; padding:3px 7px`.

**Selection default:** the first detected volume (if any exist) is preselected on open, matching the demo's `form.vol: 0` default. If zero volumes are detected, nothing is preselected — the Create button (and `⌘↵`) stays disabled until the user chooses a folder. This is the only field-level gate on Create; title and filename root are never required (see below).

### Catalog title / filename root (CRT-04)

Two-column grid (`grid-template-columns:1fr 1fr; gap:14px`). Both fields 34px, `border-radius:7px`, `--p2` fill, 1px `--l` border, `padding:0 10px`:

- "Filename root" (11px/600 uppercase label) — mono input, 12.5px, `flex:1; min-width:0` (**diverges from the demo's literal `width:62px` input** — that fixed width was sized for the demo's short placeholder text and would clip a real filename; the real field fills the column), placeholder = a slugified version of the source name (lowercase, non-alphanumeric runs collapsed to a single `-`). A fixed `.json / .html` suffix (12px mono, `--fn`, `flex:none`) sits inside the same field, `gap:2px`. Left blank, falls back to the slugified placeholder value, matching the title field's never-block-Create rule.

### Options (CRT-05)

Section label "Options" (same 11px/600 uppercase style), three toggle rows (`gap:10px; cursor:pointer` per row):
- Track 30×17px, `border-radius:9px`, `padding:2px`; knob 13px circle. On: `--ac` track, `var(--onac)` knob (corrected, see Color). Off: `--ch` track, `var(--fn)` knob.
- Label 12.5px + mono note 11px `--fn`, both to the right of the track.

| Toggle | Label | Note | Default |
|---|---|---|---|
| Write HTML | "Also write HTML catalog" | `{root}.html` (dynamic) | **on** |
| Copy to secondary location | "Copy both files to secondary location" | dynamic — see below | **off** |
| Include hidden files | "Include hidden files" | (none) | **off** |

**Defaults diverge from the demo's `[true, true, false]`** on the middle toggle: the demo starts "copy to secondary" on to keep its always-visible preview line populated for the mock; a real fresh install has no secondary location configured yet, so defaulting it on would force a folder-picker prompt on the very first open. `write-HTML` stays on (matches v1/v2's always-write-both default and `SET-04`'s eventual default), `include-hidden` stays off (matches conventional file-manager behavior).

**Secondary-location toggle bootstrap (ahead of Phase 26's Settings surface) — a genuine GUI-only capability, following the precedent `23-UI-SPEC.md` set for RAIL-05's directory chip:** turning this toggle **on** for the first time (no `storcat-secondary-directory` localStorage key set, following the established `storcat-*` convention) immediately opens the native folder picker via the existing `SelectDirectory` binding. Cancelling that dialog reverts the toggle to off. Choosing a folder persists it to `storcat-secondary-directory` and the note text becomes the real path. On subsequent opens (or subsequent toggles within the same session) with a path already persisted, toggling on reuses it with no dialog. Toggling off never clears the persisted value. Once a path exists, clicking the note text re-opens the picker to change it — the only editing affordance this phase builds; the full catalog-directory-style management surface belongs to `SET-04` (Phase 26).

## Step 2 — Scanning Contract (CRT-07, CRT-08)

Non-scrollable body: `flex:1; padding:22px 18px; display:flex; flex-direction:column; gap:22px`.

**Two sub-states of `scanning`, both rendering this same shell — never a spinner in either (project-wide "progress is always a real number" rule):**

1. **Percentage-known** — the selected source is a detected **volume** (Statfs total already known from the card list), or a **folder** whose count-only pre-pass has finished.
2. **Counting (indeterminate)** — the selected source is a **folder** and the fast count-only pre-pass (`25-CONTEXT.md`) has not yet resolved a total. This is the one place this phase must show progress with no percentage available at all — resolved below without a spinner.

### Percentage-known layout

- Title row (`display:flex; align-items:baseline; justify-content:space-between`): catalog title (14px/500) left, `{pct}%` (14px mono, `--ac`) right.
- Progress track: 6px height, `border-radius:3px`, `--ch` background; fill `--ac`, `width:{pct}%`.
- Counters line (11.5px mono `--dm`, `gap:16px`): `{seen} files` · `{seenBytes}` · `{eta}` — `eta` reads `"finishing…"` at `pct ≥ 100`, else `"about {N}s left"` computed from current throughput, never a static placeholder.
- "Walking" label (11px/600 uppercase `--dm`) + current absolute path (11.5px mono `--ac`, `word-break:break-all`, `animation: scpulse 1.4s ease-in-out infinite` — opacity 1 → .35 → 1, the one permitted looping animation in the app, already named in the handoff's Transitions table).
- Log box (`--ch` fill, `border-radius:9px`, `padding:12px; max-height:300px; overflow:hidden`): newest-first `+ /path` lines (11px mono `--dm`), **capped at 9 retained lines** (`25-CONTEXT.md`'s "retention limit" discretion, resolved as the handoff's own literal cap) — no virtualization needed at 9 items, no scrollbar (the cap keeps it always within the fixed height).
- Footer row (`margin-top:auto; gap:12px`): "Run in background" outlined button (32px, 1px `--l` border, `border-radius:8px`, 12.5px `--dm`) + helper text "Progress also shows in the status bar." (12px `--fn`).

### Counting (indeterminate) sub-state — the no-spinner resolution

Per `25-CONTEXT.md`'s locked backend decision (fast count-only pre-pass for a plain folder, to avoid a double-I/O two-pass scan): while the pre-pass runs, there is genuinely no total to compute a percentage from, so **neither a fabricated percentage nor a progress-bar fill renders** — showing either would violate the "always a real number" rule by displaying a number that isn't one. Instead:

- Title row: catalog title (14px/500) left, **`"Counting…"`** (14px mono, `--dm` — not `--ac`, since this is not yet progress) right, replacing the `{pct}%` slot.
- **Progress track is not rendered at all** during this sub-state (no empty/striped/animated placeholder bar — omitting it entirely is quieter and more honest than an indeterminate bar, and avoids the exact motion-without-meaning the "no spinners" rule exists to prevent).
- Counters line collapses to a single value, still a real, live, incrementing number: `{seen} files found so far` (11.5px mono `--dm`) — no bytes, no ETA (both genuinely unknown pre-total).
- "Walking" label + pulsing current path render identically to the percentage-known layout — this part of the contract needs no total and is already a real, live value.
- Log box, "Run in background" footer: identical to the percentage-known layout.
- The instant the pre-pass resolves a total, the state transitions to percentage-known **in place** (no re-mount, no transition animation beyond the progress bar's normal live fill) — `pct` starts wherever the now-known total puts the already-counted `seen` value, not from 0.

### "Run in background" (CRT-08)

Clicking it calls the same `onClose` as any other close path — the slide-over exit-animates closed exactly as it would for Cancel, while the scan itself continues uninterrupted in Go (the `context.Context` driving the walk is owned by `app.go`, not by the slide-over's mount state). See the Background Handoff Contract below for what appears in its place.

## Cancellation Contract (CRT-09, CRT-13)

**During the `scanning` state (both sub-states), the three applicable close paths — Escape, `×`, scrim click — cancel the scan**, not just close the panel: they cancel the underlying `context.Context`, discard the partial in-memory walk state (no write occurs — `25-CONTEXT.md`: "a user cancel and a window close mid-scan write nothing"), and then exit-animate closed exactly like any other close. **No confirmation dialog** — cancelling during a scan destroys nothing that was ever written to disk, so there is nothing a confirmation would protect (contrast with Phase 27's Trash confirmation, which does protect existing files). This matches the project's established anti-friction stance (`REQUIREMENTS.md`'s Out of Scope table already rejects a "type to confirm" gate even for destructive Trash operations).

**CRT-13 (window close mid-scan) is enforced entirely on the Go side** via the existing `beforeClose` hook (`app.go:192`, per `25-CONTEXT.md`) — there is no renderer-side dialog, confirmation, or visual state for this path. If a scan is in-flight (foreground or backgrounded) when the OS close event fires, the walk is cancelled and nothing is written before the window actually closes. No UI-SPEC contract is needed for this path beyond confirming it produces **no** intermediate screen — the app simply closes.

## Error State Contract (CRT-10, CRT-11)

Triggered when the volume disappears mid-scan (`25-CONTEXT.md`: distinct from a user cancel — this is the *only* path that offers a partial-write option). Body: `flex:1; padding:22px 18px; display:flex; flex-direction:column; gap:20px`.

- Row 1 (`gap:12px`): round `!` badge (30px, `border-radius:50%`, `#e5534b` on `rgba(229,83,75,.16)`, 15px glyph) + column: headline **"Stopped at {pct}% — the volume went away"** (14px/600) + sub-line **"{mountPath} · {seen} files walked"** (11.5px mono `--dm`).
- Error log box (`--ch` fill, `border-radius:9px`, `padding:12px; gap:4px`): chronological (not newest-first — this is a short, fixed terminal sequence of what happened right before the stop, not a live-appending log) `read error: {path} — input/output error` lines in `#e5534b` (11px mono, `word-break:break-all`), followed by a final `--dm` summary line ("volume {mountPath} disappeared — card removed or failing").
- Explanation paragraph (12.5px, `--dm`, `line-height:1.6`): **"Nothing was written yet. A partial catalog is still useful for a failing card — it records what could be read, and marks the gap."** — verbatim from the handoff.
- Actions row (`margin-top:auto; gap:10px`):
  - **"Write partial catalog"** (primary, 34px, `--ac` fill, `--onac` text, `border-radius:8px`, 13px/600) — writes the atomic partial catalog (with the unreadable-subtree marker, shape resolved in plan-phase's research pass per `25-CONTEXT.md`), then transitions to the **partial** flavor of the Done state (see below). Button disables for the duration of the (fast, single-write) call — no separate "writing…" screen, consistent with no other local operation in this app getting one.
  - **"Retry scan"** (outlined, 34px, 1px `--l` border, `border-radius:8px`, 12.5px, hover border `--ac`) — returns to the `scanning` state on the **same already-selected source** (not back to the form/picker — CRT-11 says "retry the scan," not "re-pick a volume"), restarting from 0%/0 files.
  - **"Cancel"** (text, 34px, no border, 12.5px `--dm`) — closes the slide-over via the standard close path; nothing was written (the error state itself never writes anything unless "Write partial catalog" was clicked).

## Done State Contract (CRT-12)

Body: `flex:1; padding:22px 18px; display:flex; flex-direction:column; gap:20px`. **Two flavors — complete and partial — sharing one layout:**

- Row 1 (`gap:12px`): round `✓` badge (30px, `border-radius:50%`, `--ac` on `--acs`, 15px glyph — **unchanged for both flavors**, still a success color, since something was successfully written either way) + column: title **"{catalogTitle} catalogued"** (14px/600) + doneLine (11.5px mono `--dm`): `"{files} files · {bytes} · {duration}"` complete, or `"{files} files · {bytes} · stopped at {pct}%"` partial (duration is meaningless for a scan that didn't finish — swap it for the stop point instead of omitting the third value). **Partial flavor adds a small tag** next to the title: `"partial"` (11px/600, `#f0b429` on `rgba(240,180,41,.14)`, `border-radius:5px; padding:2px 7px` — reuses the exact warning-tag styling already declared for the volume card's "read errors" tag, no new color).
- Written-files list (`display:flex; flex-direction:column; gap:1px`), one row per file actually on disk (rows present per the toggles that were active — HTML row only if HTML was requested, secondary-copy row only if enabled; a partial write still follows this same toggle-gated row set, just with the partial data's real sizes): 8px `--ac` square (`border-radius:2px`) + mono path (11.5px, `word-break:break-all`) + size, right-aligned via `margin-left:auto` (**no fixed-width column**, unlike the palette's 74px size column — the demo does not fix this one, and there's no dense multi-row alignment need here since every row shares the same left-aligned path start), `1px solid var(--l2)` separator per row.
- Actions row (`gap:10px`): **"Open in workspace"** (primary, 34px, `--ac` fill, `--onac` text, `border-radius:8px`, 13px/600) — one of CRT-01's five close paths: prepends the new catalog to the rail, selects it, closes the slide-over via the standard animated exit. **"Catalog another volume"** (outlined, 34px, 1px `--l` border, `border-radius:8px`, 12.5px, hover border `--ac`) — **does not close the slide-over**; resets the form (title/root/toggles back to defaults, volume list re-enumerated fresh) and returns to the `form` state in the same still-open panel — no re-entry animation, since the panel itself never left.

## Background Handoff & Status Bar Contract (CRT-08)

**`25-UI-SPEC.md` is the first phase to add a right-aligned segment to the status bar** — `23-UI-SPEC.md` explicitly reserved this space ("omitted entirely this phase rather than reserved as empty space") pending exactly this capability. `.ws-status` changes from three left-aligned segments with no distribution rule to `justify-content: space-between`, adding a fourth, conditionally-rendered, right-aligned segment:

| Condition | Segment |
|---|---|
| No scan running (backgrounded or otherwise) | *(nothing — status bar keeps its exact Phase 23 three-segment appearance)* |
| Backgrounded scan, percentage known | `● scanning {name} · {pct}%` — **exact copy, locked by CRT-08** |
| Backgrounded scan, still in the counting sub-state | `● scanning {name} · counting…` — Claude's-Discretion extension of CRT-08's literal copy for the one case it doesn't cover (no percentage exists yet); same visual treatment |

Styling: 11px mono, `--ac` (both the `●` glyph and the text — a static color, not an animated pulse; the in-panel WALKING text is the app's one permitted looping animation, and duplicating it in the chrome-level status bar would be a second, more distracting instance of the same motion). **The `●` is a static glyph, not an animated indicator.**

**Clicking the segment re-opens the create slide-over directly into its current live state** (`scanning`, at whatever percentage/log content the background scan has already reached) — not back to the `form` step. This is the mechanism by which a user "gets the scan back," and it is why the slide-over's internal step state must be lifted to `AppContext` (or an equivalent shared store) rather than kept as `CreateSlideOver`-local state that would be lost across the close/reopen the background handoff performs.

**"+New" pill and the rail/tree empty-state "Catalog a volume" CTAs, while a scan is already running (foreground or backgrounded):** disabled — `aria-disabled="true"`, dimmed (`opacity:.5` equivalent via `color:var(--fn)`), `cursor:not-allowed`, `title="A scan is already running — open it from the status bar."` This is the resolution to `REQUIREMENTS.md`'s Out-of-Scope "Multi-scan queue" line ("One scan at a time; 'Run in background' already covers the real workflow") — rather than silently ignoring a click or opening a confused second form, the entry points are disabled and the status-bar segment is the one live path back into the running scan.

## Entry Points (RAIL-06)

This phase wires four previously-inert affordances to open the same single `CreateSlideOver` instance, defaulting to the `form` step (unless a scan is already running — see above, in which case they are disabled instead):

- `CatalogRail`'s "+ New" pill (`ws-new-pill`, currently rendered with no `onClick` per `23-UI-SPEC.md`'s explicit "stays inert this phase" note) — this is `RAIL-06` itself.
- The rail's empty-state "Catalog a volume →" link (inert since Phase 22).
- The tree-pane empty-state primary "Catalog a volume" button (inert since Phase 22).
- The tree-pane empty-state secondary "Choose catalog folder…" button — opens the slide-over **directly to the folder-picker path** (equivalent to landing on the form step with "choose any folder" already invoked), not the generic volume-card list, since its label promises a folder picker specifically.

Opening the slide-over from any of these also closes the palette if it happens to be open (mutual z-200 exclusion, see Z-Index section).

## UI Considerations

Generated per `ui-consideration-probe.cjs` over 8 declared surfaces (form shell, volume/folder picker, title+root+WILL-WRITE, options toggles, scanning body, error body, done body, background handoff/status-bar), resolved in autonomous mode per `25-CONTEXT.md`'s "Smart discuss (autonomous)" mode.

**Applicable: 38 — resolved 38 (31 explicit, 7 backstop), unresolved 0.**

### E1 — Slide-over shell (modal / interactive-control)

| Category | Status | Resolution |
|----------|--------|------------|
| empty | not applicable | The shell has no data-driven content of its own; body content is entirely governed by the four states below. |
| loading | ✅ explicit | The shell mounts synchronously on open (same as the palette); no loading state for the panel itself, only the scanning body's own two sub-states. |
| error | ✅ explicit | The error *state* (CRT-10) is a full body state, not a shell-level error; the shell itself has no failure mode. |
| overflow | ✅ explicit | The form body is the only scrollable region (`flex:1; overflow-y:auto`); scanning/error/done bodies fit without scrolling by design (fixed-count log/written lists). Header (52px) and form footer (62px) never scroll. |
| partial | ✅ explicit | Reopening mid-exit-animation snaps back open (clears the pending unmount timer) rather than queuing a second animation — explicit in the Shell contract above. |
| long-text | not applicable | The shell renders no variable-length text of its own. |

### E2 — Volume/folder picker (list-collection / interactive-control)

| Category | Status | Resolution |
|----------|--------|------------|
| empty | ✅ explicit | Zero detected volumes: the card list renders with no rows (no fabricated "no volumes" message — the "…or choose any folder" link is always present and is the answer to an empty list), and Create/`⌘↵` stay disabled until a folder is chosen. |
| loading | 🧪 backstop | Volume enumeration (stdlib `os.ReadDir`/`Statfs`, `25-CONTEXT.md`) is expected to be fast enough that no loading treatment is needed; verified by observation, not a timing assertion — no spinner permitted either way. |
| error | ✅ explicit | A volume that fails its root-level read probe is exactly the `read errors` tag case — there is no separate picker-level error state beyond that per-card status. |
| populated | ✅ explicit | Card list + chosen-folder pseudo-card, fully specified above. |
| partial | ✅ explicit | A mix of `mounted` and `read errors` cards in the same list is expected and handled per-card — selecting a `read errors` card is still allowed (the scan will surface the real failure live, per CRT-10). |
| overflow | 🧪 backstop | An unusually long volume list (many external drives) is not covered by the handoff; resolved by giving the card-list container the same `flex:1; overflow-y:auto` treatment as the rest of the form body rather than capping card count — verified visually, not by a boundary test. |
| zero-one-many | ✅ explicit | Zero → empty case above. One or many → identical card template, first one preselected. |
| long-text | ✅ explicit | Card name/path ellipsize single-line (specified above); a long secondary-toggle path wraps inside the WILL WRITE box's `word-break:break-all`, not the card. |

### E3 — Title, filename root, WILL WRITE preview (form)

| Category | Status | Resolution |

| error | ✅ explicit | No client-side validation error state — a filename root containing characters invalid for the OS's filesystem is not pre-validated in the UI; the write itself would surface any real failure through the normal error path if it ever occurred (out of scope to pre-empt here). |

| long-text | ✅ explicit | A very long catalog title or filename root is not truncated in the input (native field behavior); in the WILL WRITE preview it wraps via `word-break:break-all`, never overflows the box. |
