## Threat model

### Trust boundaries

| Boundary | Description |
|----------|-------------|
| user-typed filename root → the destination path passed across the bridge | Free text becomes part of a filesystem path |
| persisted secondary-location value in browser storage → a write destination | A value read back from storage is used as an output directory |

### STRIDE threat register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-01 | Tampering | Filename-root free text reaching the write path | high | mitigate | Carried from plan 25-01: the containment gate in the binding rejects any root whose joined destination escapes the output directory. This surface adds no second validation layer and no shell invocation — the create flow builds paths only through path joining, never string concatenation, and runs no external command |
| T-25-20 | Tampering | A tampered persisted secondary-location value used as an output directory | medium | mitigate | The value is only ever passed as the secondary directory argument, where the binding's containment check validates the resolved copy destinations before any write |
| T-25-21 | Information Disclosure | The preview reveals whether a given path already exists on the user's disk | low | accept | The check reads only the catalog listing already loaded into application state for the user's own configured directory; no new filesystem surface is exposed |
| T-25-SC | Tampering | Dependency supply chain | high | mitigate | No package install in this plan — the toggle, badges and progress bar are hand-built markup and styling per the design contract's registry-safety section. `25-RESEARCH.md`'s Package Legitimacy Audit records zero `[ASSUMED]`, `[SUS]` or `[SLOP]` packages |
