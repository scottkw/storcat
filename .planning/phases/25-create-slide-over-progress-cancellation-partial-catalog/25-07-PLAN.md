<objective>
Close the loop on the two terminal states: the distinct error state a vanished volume produces with its salvage, retry and walk-away options, and the done state that lists exactly what landed on disk — plus the four entry points that open this panel and their disabled behaviour while a scan is running.

Purpose: an interrupted scan is the case that separates a tool you trust from one you don't. Silently writing a truncated catalog, or silently discarding a walk the user could have salvaged, are both worse than an honest stop with a named recovery. This plan is where that honesty becomes visible.

Output: the error and done bodies, the four wired entry points, and the phase's completed verification matrix.
</objective>

| Boundary | Description |
|----------|-------------|
| retained partial tree → destination file, triggered from the interface | A user gesture in the error state causes a write of data captured earlier |
| read-error paths from a failing volume → rendered interface | Path strings from a failing device are rendered as text in the error log |
| four entry points → one shared panel | Multiple affordances mutate the same overlay state |
