<objective>
Close PLT-05: a hit in the palette becomes a selected, centred row in the tree.

The mechanism is four steps across an asynchronous gap — switch catalog, wait for the flat tree to land, expand every ancestor, select and scroll — and this codebase has two specific traps waiting in it, both confirmed by reading the source rather than inferred:

`SET_EXPANDED` **replaces** the expansion map (`frontend/src/contexts/AppContext.tsx:123-126`). It was written correctly for its two existing callers — expand-all passes the full set, collapse-to-root passes an empty object — and a third caller with merge semantics was never anticipated. A reveal that dispatches the ancestor chain alone collapses every other branch the user had open. `24-UI-SPEC.md`'s own prose describes the required behavior as merging; the reducer does not do that, so the merge has to happen at the dispatch site.

`virtualizer.scrollToIndex` called in the same effect as the expansion dispatch targets the pre-expansion row list. The virtualizer object in any given render is bound to that render's `count`, derived from `visibleIndices`, derived from the `expanded` map that has not committed yet. `TreePane.tsx` already models the fix in its own load-effect / scroll-reset-effect pair.

Purpose: get both right on the first commit, with the multi-branch survival check verified live rather than reasoned about — the frontend has no test framework and TEST-01 is a locked deferral, so the browser pass is the safety net.

Output: `frontend/src/lib/reveal.ts`, `pendingReveal` in the reducer, TreePane's two reveal effects, and the palette's activation handler.
</objective>
