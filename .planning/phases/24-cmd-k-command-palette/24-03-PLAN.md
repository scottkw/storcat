  1. **Assumption:** locking `overflow: hidden` on the single `.ws-root` element is sufficient to stop scrolling behind the scrim. The workspace is a fixed-height flex shell whose only scroll regions are `.pane-scroll` descendants, so no separate `document.body` lock should be needed — but the app has never had a true modal before, so this is reasoned from the CSS, not observed. Task 2's behavior assertion is the check.

If 24-04's result list introduces a second tab stop, the trap must still cycle correctly — the implementation is written for N stops, not for one, so this stays an assumption about the *current* DOM rather than about the hook.

  <action>
    Create `frontend/src/hooks/useModalBehavior.ts` exporting an interface `ModalBehaviorOptions` with `isOpen: boolean`, `onClose: () => void`, an optional `initialFocusRef?: React.RefObject<HTMLElement | null>`, and an optional `scrollLockSelector?: string` defaulting to the shell root class; an interface `ModalBehavior` with `containerRef: React.RefObject<HTMLDivElement | null>`; and `export function useModalBehavior(options: ModalBehaviorOptions): ModalBehavior`. Export a module-private constant naming the focusable-descendant selector — anchors with href, non-disabled button, input, select and textarea, and any element with a tabindex that is not negative one.

    Structure the hook as **one `useEffect` whose dependency array is exactly `[isOpen]`**. This single decision is what makes the hook fit Phase 25: React runs an effect's cleanup when a dependency changes, so cleanup keyed on `isOpen` fires on the true→false transition — while the consumer is still mounted and still animating out. An effect keyed on the empty array would clean up only at unmount and would leave Phase 25's page scroll-locked for the whole 260ms exit. Guard the effect body with an early return when `isOpen` is false so a consumer mounted closed — the common case, since every consumer starts closed — runs none of the four behaviors.

    Hold `onClose` in a ref that a separate tiny effect keeps current on every render, and read it through that ref inside the keydown handler. Consumers pass inline arrow functions; putting `onClose` in the dependency array would re-run the whole effect on every parent render, thrashing the scroll lock and re-capturing the focus-restore target against the wrong element.

    Inside the effect, in this order:
    1. **Capture the restore target.** Read `document.activeElement`, store it in a ref if it is an `HTMLElement`. This is captured before focus moves, so it records what the user was on when the overlay opened rather than being hardcoded to a specific trigger — Phase 25, 26 and 27 each open from a different control.
    2. **Move initial focus.** Focus `initialFocusRef.current` when supplied; otherwise focus the first focusable descendant of `containerRef.current`; otherwise focus the container itself. Do this synchronously in the effect body, not in a timeout — there must be no frame in which the overlay is visible but unfocused.
    3. **Lock scroll.** Resolve the lock element with `document.querySelector(scrollLockSelector)`, falling back to `document.body`. Save its current inline `overflow` value into a ref before overwriting it with hidden, so the cleanup restores the previous value rather than blindly clearing it.
    4. **Register one `window` keydown listener** handling both remaining behaviors. On Escape: call `preventDefault()` and invoke the current `onClose` through the ref — this fires regardless of which element inside the overlay has focus, which is why it lives on `window` and not on the panel. On Tab: read the focusable descendants of `containerRef.current` fresh on each keypress (the palette's row list changes between keystrokes, so a list captured at open time would be stale); if there are none, call `preventDefault()` and keep focus on the container; if the active element is outside the container, `preventDefault()` and focus the first; if Shift is held and the active element is the first, `preventDefault()` and focus the last; if Shift is not held and the active element is the last, `preventDefault()` and focus the first.

    The cleanup returned from the effect must, in order: remove the keydown listener, restore the saved `overflow` value on the lock element, and refocus the captured restore target only when it is still `isConnected` — a trigger removed from the DOM while the overlay was open must not throw and must not steal focus to a detached node.

    The hook must never call `onClose` itself when `isOpen` is false: because the effect body returns early, no listener is registered while closed, so a defensive double-close from a consumer is structurally a no-op rather than something the hook has to defend against with a flag.

    Do not add a dependency. Do not use the native dialog element or the inert attribute — both were considered in `24-RESEARCH.md` and neither is the locked approach. Do not reference the palette by name anywhere in this file; it is the first consumer, not the only one.
