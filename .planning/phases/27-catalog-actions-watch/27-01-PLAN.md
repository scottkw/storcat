**2. `internal/catalog/rename.go` — new file, package `catalog`.**

Export exactly one function: `RenameCatalog(jsonPath string, newTitle string) error`.

Sequence:
- `strings.TrimSpace(newTitle)`; empty → return `fmt.Errorf("rename %s: title is empty", jsonPath)` before touching the filesystem.
- `os.ReadFile(jsonPath)`.
- Split the on-disk envelope. If the first non-whitespace byte is `[`, decode the document into `[]json.RawMessage`; element 0 is the tree-root object and every remaining element is carried through verbatim. Otherwise the whole document is the tree-root object. A document that is neither (or fails `json.Unmarshal`) returns a wrapped error and writes nothing.
- Set the title on the root object with an **order-preserving rebuild**, not a full unmarshal-and-remarshal. Implement an unexported helper `setRootStringField(obj []byte, key string, value string) ([]byte, error)`: build a `json.NewDecoder(bytes.NewReader(obj))`, consume the opening `{` via `Token()`, then loop `for dec.More()` reading each key with `Token()` and each value into a `json.RawMessage` via `dec.Decode(&raw)` — `json.RawMessage` preserves the value's source bytes verbatim, including all nested whitespace. Collect the `(key, raw)` pairs in document order. If `key` already exists, replace its raw value in place; otherwise append the pair at the end. Re-emit `{` + `"k":v` pairs joined by `,` + `}`. This is why a full round-trip is forbidden: `map[string]json.RawMessage` re-marshals in alphabetical key order, and unmarshalling into `models.CatalogItem` silently drops both the v1 array's trailing `tree` report element and any unrecognized key a v1 bash-script catalog carries. The rebuild touches only the root object's own key list; every nested value, including the entire `contents` subtree, is copied byte-for-byte.
- Reassemble: array envelope → `[` + rebuilt root + `,` + remaining raw elements + `]`; bare object → the rebuilt root alone.
- `WriteFileAtomic(jsonPath, out, 0644)`.
- Derive the HTML companion with the repo's one pairing convention: `strings.TrimSuffix(jsonPath, ".json") + ".html"`. `os.Stat` it; `os.IsNotExist` → return `nil` (per `27-CONTEXT.md`: rename is allowed on a catalog with no `.html`, with no blocked or greyed state). Any other stat error → wrapped error.
- Read the HTML, patch it with an unexported `rewriteHTMLTitle(doc []byte, newTitle string) []byte`, `WriteFileAtomic(htmlPath, patched, 0644)`.

`rewriteHTMLTitle` replaces the text between the first `<title>` and the following `</title>`, and the text between the first `<h1>` and the following `</h1>`, each with `html.EscapeString(newTitle)`. Use `strings.Index`-delimited substring replacement, mirroring `BrowseCatalogs`'s own read-side extraction pattern — never a full HTML regeneration, because the tree structure, the directory/file counts and the formatted byte total in the generated markup must stay byte-identical. A tag pair that is absent is skipped, not treated as an error. This dual-site rewrite is the post-research resolution in `27-CONTEXT.md`: `internal/catalog/service.go` writes `html.EscapeString(title)` into both `<title>%s</title>` and `<h1>%s</h1>`, so patching only the tag ACT-02's wording names would leave the page heading contradicting its own tab title.

  <action>
Fix the read half of the round trip the tracer opened, so a renamed title actually reaches the rail.

Add `"html"` to `internal/search/service.go`'s import block.

Add an unexported helper `extractJSONTitle(data []byte) string` in the same file. It unmarshals into a minimal probe — a local struct with a single `Title string` field tagged `json:"title"` — trying the bare-object shape first and, on failure, the `[]probe` array shape and taking element 0. Any decode failure returns the empty string. Go's decoder discards unmatched keys without allocating for them, so the probe costs roughly one more lexical pass over bytes `BrowseCatalogs` has already read into memory and already scanned once via `json.Valid` inside `detectParseError`; that is the honest, accepted cost of making the JSON field authoritative, and it is why the probe is called only when `parseErr == ""`.

Restructure `BrowseCatalogs`'s title resolution into an explicit three-tier chain, replacing the current HTML-then-filename pair:
1. When `parseErr == ""`, call `extractJSONTitle(data)` on the bytes already read for the parse check; a non-empty result wins outright and no HTML read is attempted for the title.
2. Otherwise fall back to the existing `<title>` extraction from the sibling `.html` — with the extracted substring now wrapped in `html.UnescapeString(...)` before assignment. This is the locked read-side escaping fix: the write side has always escaped correctly via `html.EscapeString` (twice, in `internal/catalog/service.go`), while the reader used a raw `strings.Index` substring with no unescape anywhere in the repo, so a title containing `&` displayed as the literal `&amp;`. Rename is precisely the feature that makes users type `&`.
3. Otherwise fall back to the filename minus `.json`, unchanged.

Note the ordering constraint this creates: the parse-error read of `filePath` currently happens *after* the HTML title block. Move the title resolution so it runs after `data`/`parseErr` are available, or hoist the file read — whichever keeps `BrowseCatalogs` to exactly one `os.ReadFile` of the `.json` per catalog. Do not add a second read of the same file.

Do NOT apply `html.UnescapeString` to the JSON-sourced title. The JSON field stores the user's literal string; unescaping it would silently corrupt a title that legitimately contains an entity-looking substring.
