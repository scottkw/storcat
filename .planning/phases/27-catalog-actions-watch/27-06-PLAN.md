<recorded_decision id="shutdown-hook">
`27-RESEARCH.md` Assumption A2 flags this as architecture guidance resting on Wails' documentation rather than a direct source read, and `27-CONTEXT.md` names package layout but not this specific hook choice. Deciding it explicitly here.

**Decision: add `OnShutdown: app.shutdown` to `main.go`'s `options.App` and release the watcher there, in addition to keeping `beforeClose` untouched.**

`main.go` currently registers only `OnStartup`, `OnDomReady` and `OnBeforeClose`. `beforeClose` is not a reliable unconditional cleanup hook: it can *return true to prevent the close*, which it already does for an active scan, so it runs on a path that may not lead to a quit at all and its early-return branches are conditional. `OnShutdown` fires once, unconditionally, after the close is confirmed. WATCH-03 requires genuine release, so the release belongs on the path that always runs.

Do **not** move any existing `beforeClose` logic. The scan-cancellation interception there is load-bearing for CRT-13 and was verified live in Phase 25; this plan adds a hook beside it and changes nothing about it.

Residual risk: `OnShutdown`'s exact firing semantics come from Wails documentation, not from a source read of Wails v2 in this session. Verified behaviorally by the live quit check in plan `27-07` rather than assumed.
</recorded_decision>

**2. Create `internal/watch/watcher.go`, package `watch`.**

Export `const DefaultDebounce = 300 * time.Millisecond` — `27-CONTEXT.md`'s locked ~300ms trailing debounce, as a named constant rather than a magic number (its own discretion item, resolved toward the named constant so a future tuning has one place to change).

**The coalescer**, an unexported type holding a mutex, the window duration, the callback, a `*time.Timer` and a stopped flag:
- `newCoalescer(d time.Duration, fn func()) *coalescer`.
- `trigger()` — trailing debounce: under the mutex, stop any existing timer and set a fresh `time.AfterFunc(d, fn)`. A no-op once stopped.
- `fireNow()` — under the mutex, stop any pending timer and invoke the callback immediately. **Do not hold the mutex across the callback invocation** — release it first, or dispatch in a goroutine — so a slow callback cannot block the event loop or deadlock against a concurrent `trigger()`.
- `stop()` — under the mutex, stop any pending timer and set the stopped flag so a late `trigger()` cannot resurrect it after `Close()`.

**The watcher:**
- `New(dir string, debounce time.Duration, onChange func()) (*Watcher, error)`. Validate `dir != ""` and `onChange != nil` with wrapped errors before allocating anything. A non-positive `debounce` falls back to `DefaultDebounce`. Create the `fsnotify.Watcher`, `Add(dir)` — **the single directory only, never a walk of its subdirectories.** fsnotify is documented as non-recursive, and that is a non-issue here because catalogs are flat `.json`/`.html` files directly inside one directory; a recursive walk would be both unnecessary and wrong. If `Add` fails, close the fsnotify watcher before returning the error so the OS handle is not leaked on the failure path.
- Start one goroutine running a `select` loop over three channels: the fsnotify `Events` channel, the fsnotify `Errors` channel, and an internal `done` channel. Return from the loop when any of the three is closed or `done` fires.
- **Events branch:** ignore an event whose name has neither a `.json` nor a `.html` extension. For the rest, call `trigger()` when the op has any of `Create`, `Write`, `Remove`, `Rename`. Do **not** attempt to filter out this app's own writes: `WriteFileAtomic` uses the very temp-then-rename pattern fsnotify documents as indistinguishable from an external editor's atomic save, and the debounce plus an idempotent full re-list already handle it correctly. `27-RESEARCH.md` Pitfall 5 names in-flight-path tracking as unnecessary complexity — do not build it.
- **Errors branch:** must be drained in the same `select`. An unread errors channel can stall the watcher outright. On any error, including `fsnotify.ErrEventOverflow`, call `fireNow()` — "we may have missed events" and "something changed" have the same correct recovery, an idempotent re-list, and there is no delta to reconcile. Do not log-and-drop, and do not tear the watcher down on an error.
- `Close() error` — guard with a `sync.Once` so it is idempotent and safe to call twice (WATCH-03's toggle-off path and the app-quit path can both reach it). Inside: `stop()` the coalescer, close `done`, then `Close()` the fsnotify watcher and return its error. This genuinely releases the inotify fd, kqueue fd, or Windows handle; WATCH-03 requires release, not merely ignoring events.

**Hard constraint:** this package must NOT import `github.com/wailsapp/wails/v2/pkg/runtime`, must not take a Wails `context.Context`, and must not know that a frontend exists. `27-CONTEXT.md` states this as a hard constraint and `app.go:167-189`'s own comment is the precedent: `internal/catalog` and any new watcher package must stay usable from the CLI with no Wails runtime attached (COMPAT-04). The caller supplies a plain `func()`.

Document at the top of the file that the callback may be invoked from a timer goroutine, so the caller's closure must be safe to call concurrently with its own state.
