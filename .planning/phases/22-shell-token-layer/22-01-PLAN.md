`lum(hex: string): number` — port verbatim from 22-RESEARCH.md: strip one leading hash, take byte pairs at offsets 0/2/4, divide by 255, apply `x <= 0.03928 ? x / 12.92 : Math.pow((x + 0.055) / 1.055, 2.4)`, return `0.2126*r + 0.7152*g + 0.0722*b`. Keep the `0.03928` threshold exactly — it is the WCAG constant the prototype uses and must not be unified with the `0.04045` constant used by the OKLab path below.
`mixHex(a: string, pct: number, b: string): string` — perceptual OKLab blend, per the locked CONTEXT.md decision (sRGB channel averaging is explicitly rejected). Linearize each sRGB channel with `x <= 0.04045 ? x / 12.92 : Math.pow((x + 0.055) / 1.055, 2.4)`, convert linear RGB to LMS with the Ottosson M1 matrix, take the cube root of each LMS component, convert to Lab with the M2 matrix, lerp L/a/b by `pct / 100` toward `a` (so `pct = 100` returns `a` and `pct = 0` returns `b`), then invert: M2 inverse, cube each component, M1 inverse, apply `x <= 0.0031308 ? 12.92 * x : 1.055 * Math.pow(x, 1 / 2.4) - 0.055`, multiply by 255, clamp to the closed interval 0 to 255, and `Math.round`. Return `rgb(r, g, b)`.
`mixAlpha(hex: string, pct: number): string` — the blend-with-transparent case; return `rgba(r, g, b, pct/100)` using the source channels unchanged.
`computeTokens(theme: Theme, density: Density): Record<string, string>` — a TS port of `varsFor` plus the density branch, both quoted verbatim in 22-RESEARCH.md. Enumerate the 14 token names from one module-level array so the set cannot drift: `--bg --p --p2 --ch --l --l2 --tx --dm --fn --sel --hov --ac --acs --onac`. Base seven come straight from `theme.tokens`. Derived: `--l2` = mixHex(l, 55, p); `--dm` = mixHex(tx, 66, bg); `--fn` = mixHex(tx, 44, bg); `--hov` = mixHex(tx, 8, bg); `--sel` = mixAlpha(ac, 14); `--acs` = mixAlpha(ac, 16); `--onac` = `lum(ac) > 0.45 ? '#0b0e13' : '#ffffff'`. Density variables: `--rh` `27px`/`34px`, `--rp` `6px 8px`/`10px 10px`, `--mp` `6px`/`10px`, `--hp` `7px 14px`/`11px 14px`, `--fs` `12px`/`13px` (Compact/Comfortable).
