<objective>
Prove the whole re-scan → diff path end to end on one thin slice: one entry point (the details-panel
footer), one volume, one walk, one diff, five counts on screen.

Purpose: this phase's architecture has three seams that can each fail late and expensively — the
walk/write extraction, the `lastPartial` isolation, and the Go→Wails→React diff payload. A tracer proves
all three on the executor's best early-context tokens, so an architectural dead-end costs one commit
instead of ten.

Output: `Walk` extracted, `ModTime` captured, `ComputeDiff` computing four states, `RescanCatalog`
bound, and a working 620px `RescanDialog` reachable from a real catalog.
</objective>

<assumption_delta_decision>
**Signal:** `pluralization` — `traverseDirectory`'s walk gains a *second* consumer (re-scan) where Create
was previously the only one, and `CreateCatalogWithContext` was the only way to build a tree.

**Primary noun:** the **walk** (`Service.Walk`) is now the primary tree-building operation.

**Decision: `promote`.** `Walk` is promoted to the primary, exported entry point;
`CreateCatalogWithContext` is demoted to a two-line composition (`Walk` then `WriteCatalogFrom`) — one
variant of walking, the one that also writes. This is deliberately NOT `add-alongside`: a second
traversal implementation beside the existing one is explicitly forbidden by CONTEXT ("two walkers will
drift on hidden-file handling, symlinks, and error classification").

**Invariant test encoding the generalized intent:** `TestCreateCatalog_JSONShapeUnchanged` must pass
UNMODIFIED after the promotion — it goes red the instant a future phase reintroduces a Create-only walk
path that diverges from `Walk`.
</assumption_delta_decision>
