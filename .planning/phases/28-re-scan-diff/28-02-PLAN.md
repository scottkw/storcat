<objective>
Make the locked fourth diff state actually reachable, and complete the diff's semantics.

Purpose: research proved the "unreadable is distinct from removed" decision is currently
UNIMPLEMENTABLE — a single unreadable subdirectory with the root still readable is silently DROPPED, and
diffed that is indistinguishable from `removed`. Without this plan the `unreadable` tile ships as a
permanently-zero decoration and an overwrite can destroy readable-tomorrow data.

Output: an opt-in `MarkUnreadableOnSkip` walk option, the `unreadable` and type-change diff rules, the
sum invariant, and the low-similarity signal.
</objective>

<!-- planner-discipline-allow: MarkUnreadableOnSkip -->
This is its own reviewable task by explicit instruction — it is a real behavior change to
`traverseDirectory`'s skip-and-continue path, not glue code, and it is the enabling change for the
locked fourth diff state.

Add one field to `Options`: `MarkUnreadableOnSkip bool`, default false, doc-commented to say that when
true a skip-and-continue single-entry/subtree failure (scan root still reachable) also records the
marker on that node instead of silently dropping it, and that it does NOT abort the walk. Every existing
Create call site (`CreateCatalog`'s wrapper, `startScan`) leaves it at the zero value by construction —
do not touch them.

**Branch 1 — directory-level `os.ReadDir` failure (root still reachable).** Today this builds an empty,
error-free directory node and returns it with a nil error. When the new option is set, populate that
node's existing `Unreadable`/`ReadError` fields from the failing error BEFORE the existing return, and
still return a nil error so the walk continues exactly as it does today. The `st.classify()` root-loss
branch above it is untouched.

**Branch 2 — per-child recursive failure (root still reachable).** Today this calls `recordReadError`
and then skips the child entirely, building nothing. This is the one place the "gate an existing return"
shape does not apply: when the new option is set, synthesize a minimal node for the failed child —
`Type` inferred from the `os.DirEntry` (`directory` when `entry.IsDir()`, else `file`), `Name` set to the
child's display path computed the same way every other node in this function computes it, `Size` 0,
`Contents` an empty slice for a directory — with the marker fields populated, and append it to
`contents` in place of the skip. When the option is unset, the skip is unchanged.

`recordReadError` keeps firing on both branches regardless of the option — the live `scan:progress`
read-error counter must not change behavior. The option adds a per-node marker; it does not replace the
counter.

**Tests (`service_test.go`, additive only).** Add `TestTraverseDirectory_MarksSkippedNodeWhenFlagSet`:

permission-dependent tests in this package already use.

Do NOT edit `TestTraverseDirectory_SingleEntryErrorSkipsAndContinues`. If it needs editing, the default
path was changed and the implementation is wrong.

  <action>
Extend `categorize` and `ComputeDiff` — do not rewrite 28-01's structure.

**Ordering of the categorize branches matters and is fixed:** new-node-absent → removed; old-node-absent
→ added; the new node carries the unreadable marker → `unreadable` (this must be checked BEFORE the size
and mtime comparisons, since an unreadable node has no meaningful size); old and new `Type` differ →
emit two entries, one `removed` for the old and one `added` for the new, and count both (a file where a
directory used to sit is a different entity that happens to share a path, not a comparable edit); size
differs → changed; the old node's mtime is non-zero and differs from the new node's → changed;
otherwise unchanged.

An `unreadable` entry copies the node's own `ReadError` string into `DiffEntry.ReadError` and leaves
`NewSize` at zero — no size is knowable for an entry that failed to read.

**Sum invariant.** After categorization, the five counts must equal the number of distinct paths across
both flattened maps, plus one extra for each type-change pair (which contributes two entries for one
path). Compute the counts from the entry list rather than incrementing in two places, so the invariant
holds by construction rather than by discipline.

**Similarity signal.** Add `OldEntryCount int` and `LowSimilarity bool` to `DiffResult` in
`pkg/models/catalog.go`. Set `LowSimilarity` when `OldEntryCount` is at least the minimum-entries floor
AND `(Added + Removed)` divided by the sum of all five counts is at least the threshold. Declare both as
named package-level constants in `diff.go` (floor 20 entries, threshold 0.6, per the UI-SPEC's concrete
default) so the values are greppable and tunable in one place. This is a signal only — nothing in Go
blocks or refuses on it.

**Tests (`diff_test.go`).** Add table-driven cases: `TestDiff_UnreadableIsNotRemoved` (a node present in
old, present-but-marked in new → exactly one `unreadable` entry and zero `removed`);
`TestDiff_UnreadableCarriesReadError`; `TestDiff_TypeChangeYieldsRemovedAndAdded` (one path, two
entries, correct states); `TestDiff_CountsSumToDistinctPaths` (a mixed fixture covering all five states,
asserting the sum identity); `TestDiff_LowSimilarityBelowFloor` (a 5-entry old tree replaced entirely →
`LowSimilarity` false because the floor is not met); `TestDiff_LowSimilarityAboveThreshold`.
  </action>
