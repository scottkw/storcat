# Quick Task 260901-dw8 — README release-status fix

## Problem

`README.md` lines 9-11 carry a pre-release note:

> `main` is at v3.0.0. The latest *published* release is v2.3.0, which still ships the
> older three-tab interface — the workspace described below arrives with the v3.0.0 release.
> Build from source (see Building from Source) to run it today.

That is now false. `git tag` and `gh release list` both show **v3.0.0 published
2026-08-18 and marked `Latest`**. The note tells users the shipped release is v2.3.0
and pushes them to build from source for functionality that is already in the released
binary.

## Scope

Live observation at planning time (`grep -n -iE 'v?[0-9]+\.[0-9]+\.[0-9]+|latest|release'
README.md`) found exactly one stale *release-status* statement — the note block. Every
other version mention is version **history**, which stays:

- L39-45 "Why StorCat v2.0.0? The Migration from Electron" — historical rationale
- L487 Electron v1.2.3 vs Wails v2.0.0 perf table — historical comparison
- L568-573 "Migration from v1.x" changelog entries tagged (v2.1.0)/(v2.3.0)/(v3.0.0) — history
- Install/Releases sections link to the unversioned `/releases` page — always current

## Tasks

### Task 1 — remove the stale pre-release note

- **files:** `README.md`
- **action:** Delete the three-line `> **Note:** ...` block (lines 9-11) and its trailing
  blank line. Nothing replaces it: the title already reads `# StorCat v3.0.0`, the
  Installation section already points at the Releases page, and "What's New in v3.0.0"
  follows immediately. A rewritten "v3.0.0 is the latest release" line would go stale
  again at v3.1.0 — the smallest correct diff is deletion.
- **verify:** `grep -n 'v2\.3\.0' README.md` returns only the two historical changelog
  lines in "Migration from v1.x"; `grep -n 'published' README.md` returns nothing;
  `sed -n '1,14p' README.md` shows the intro flowing straight into `## What's New in v3.0.0`.
- **done:** README makes no claim that any release other than v3.0.0 is the latest.

## Must Not

- Do not touch the historical version references listed under Scope.
- Do not hardcode a version into the Installation or Releases sections.
